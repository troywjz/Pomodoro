# M0 产品行为候选决策

状态：候选建议，待用户批准。本文澄清产品语义；具体字段、协议和事务时序由契约任务维护。现有已确定 UI 四项要求继续有效：时间数字前置进度圆圈、按钮文案居中、系统主题且 Light 首次/回退、展开收起宽度等于所在屏幕物理宽度的 10%。

## D-01 统计中的中断时长

**推荐：** 将 `actual_focus_ms` 定义为已完成与已中断专注阶段的活动时长总和；暂停区间不计。另提供 `completed_focus_ms`，只合计已完成专注阶段。完成轮数只由 completed 阶段增加，interrupted 与 skipped 分开计数。统计按阶段开始时的本地日期归属，并保存 UTC 和当时偏移供追溯。

**备选及影响：** 只统计完成段会让用户失去提前结束前的实际工作量；把中断段计作完成则会夸大完成轮次。推荐方案同时呈现投入时间与完成成果。

**验收样例：** 专注运行 10 分钟、暂停 2 分钟后中断；`actual_focus_ms=600000`、`completed_focus_ms=0`、完成轮数不变、中断数加一。一个 25 分钟完成段使两种分钟指标各增加 25 分钟、完成轮数加一。

## D-02 清理的最终确认与取消顺序

**既定输入：** `docs/requirements.md` §6 与 AC-23/24 定义“清空历史”：摘要后确认，先生成并验证可读取备份，再删除历史；配置和活动会话保留；取消不改数据；备份失败中止。`docs/requirements.md` §6 与 AC-33 定义“永久清除全部本地数据”：单独二次确认，先要求结束活动会话，然后清除历史、配置、活动快照和应用管理的备份；不新建备份，外部导出文件保留。

**新增推荐：** 两项操作分别呈现，不让清历史路径结束活动会话。清历史的取消从摘要返回原页，所有数据与活动状态均保持；确认后备份校验成功才删除历史。备份写入或验证失败时，停止操作、保留历史/配置/活动并显示“重新发起清理”，重新走完整摘要与确认。永久清除先说明影响范围；若有活动段，说明最终确认时会先结束活动段，再清除历史、配置、活动快照和应用内备份。用户在最终确认前取消时只撤销意图，所有数据及活动状态保持原样。最终确认执行结束与清除；外部导出文件全程保留。应用内具体事务顺序由契约任务评审。

**备选及影响：** 永久清除可先执行“结束活动段”，再让用户确认最终删除；若用户取消最终删除，活动已变为 interrupted 且应用保留记录。该流程产生先后可见的数据变化。本推荐把结束活动和全清放在最终确认后执行，使任一确认前取消都保持原数据/活动状态。

**验收样例：** A) running 时清空历史，摘要说明活动段/配置保留；取消后 activity 仍 running。确认时先验证备份，失败则历史/配置/activity 原样保留，页面说明清理操作已结束并提供“重新发起清理”；重新发起需重走摘要/确认。成功后仅历史清除，activity 仍 running。B) running 时永久清除；在范围摘要或最终确认任一节点取消，activity、历史、配置及应用备份均原样保留。最终确认后结束活动段并清除所有应用管理数据/备份；外部导出文件保留。每个节点都核对目标状态。

## D-03 导出范围

**既定输入：** `docs/requirements.md` §6 与 AC-21/22 要求版本化 JSON 含 schema 版本、导出时间、配置和阶段数据；CSV 用于可读统计并与 JSON/统计口径一致。MVP 暂不提供导入。

**新增推荐：** JSON 导出包含一致性快照中的配置、已提交历史、导出时间、UTC 时间戳及原时区偏移；活动段以带状态和保存时间的独立快照对象列出，不转成历史完成记录。CSV 只含已提交历史分析字段，不含配置、活动快照或凭据。两者定位为供用户查看/保存的数据导出。MVP 应用恢复使用应用内备份流程；不提供从导出文件导入或迁移的入口。

**备选及影响：** 把 CSV 扩为可重建全部应用状态会混淆分析文件与恢复数据；把 JSON 描述为可恢复备份会暗示尚未纳入 MVP 的导入能力。推荐保持 JSON/CSV 只读导出定位，应用恢复使用独立的应用内备份流程。

**验收样例：** 导出时有一段 paused 专注：JSON 含带 `paused` 状态的活动快照与既有历史，CSV 仅含已提交历史行；导出结果可解析与检查，产品界面不显示“恢复/导入此文件”入口。失败导出保留源数据并显示失败位置/原因。

## D-04 idle、已选目标与 recovery

**推荐：** 区分 `idle_without_target` 与 `idle_with_target` 的视觉语义；前者显示空轨道、占位读数和“选择阶段”，后者显示目标时长的完整轨道、阶段及“开始”。设置可修改默认时长，但只有明确选择阶段才生成待启动目标。recovery 展示最近可靠快照、暂停/无目标状态、保存时间及继续/保持暂停/放弃选项；用户选择前不推进、不补记完成。圆弧与数字只表达剩余量，阶段和状态另有文本及读屏名称。

**备选及影响：** 将两类 idle 合并会让完整圆环看似已开始计时；recovery 自动续跑可能悄悄消耗离线时间。推荐保留清楚的空闲入口和用户控制。

**验收样例：** 首次启动无预选阶段时显示空轨道、“选择阶段”；选择 focus 后显示完整目标环与“开始”，但仍为 idle。强杀后重启为 recovery；等待期间读数不变，选继续才转 running。
