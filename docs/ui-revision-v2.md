# UI 第二轮调整与验收输入

状态：用户已提出以下四项调整；产品和设计按本文件继续细化。新版完整原型与关键架构审批后再开始业务实现。

## 用户明确要求

1. 时间前方增加倒计时圆圈。
2. 按钮文字居中。
3. 主题跟随系统浅色/深色模式，默认浅色。
4. 展开与收起保持相同宽度，宽度为屏幕宽度的1/10，其他元素按比例调整以适配多种显示屏。

本轮覆盖旧设计中的固定280宽主卡、200宽mini及默认深色设定。旧截图保留为历史版本，新版单独命名并标记评审状态。

## 统一细化输入

- 屏幕采用窗口所在显示器；多显示器不取拼接虚拟桌面总宽。候选选择规则：窗口中心所在显示器，移出所有显示器时回到主显示器可见区域。
- 物理目标宽度 Wpx = round(当前显示器物理宽度 / 10)。设缩放因子s = DPI / 96，Slint逻辑宽度Wdip = Wpx / s；Figma使用逻辑尺寸表达，旁注物理输出。用户要求保持10%比例，产品先展示极窄屏的可读性取舍，不自行添加改变10%规则的最小/最大宽度。
- 展开与收起使用同一W，只变化高度和可见内容；字体、圆圈直径、间距、圆角、按钮高度按W比例定义。窗口跨屏和DPI变化由同一布局输入重算，修正到可见工作区。
- 圆圈位于倒计时数字前方，表达 remaining / target；启动完整、到期归零，暂停冻结；数字保留为准确读数，状态文字和辅助技术语义齐备。视觉刷新与计时内核分离，优先每秒刷新与静态弧线。
- 按钮文字水平、垂直居中；整块按钮接受点击；焦点/悬停/按下/禁用状态都有规格。设置和收起为独立入口。
- 主题模式为跟随系统；系统查询成功时采用当前应用主题，首次查询前或查询失败时用浅色。系统主题运行时变化应更新；两套颜色变量覆盖画面、弹窗、圆圈、数字、按钮及错误状态。
- 设计矩阵至少包含1366×768@100%、1920×1080@100%、2560×1440@125%、3840×2160@150%、混合DPI双屏。物理宽度预期分别约137、192、256、384px；逻辑宽度由各缩放因子计算。

这些细化规则用于团队消除接口歧义，产品负责写出选择理由和边界案例，设计负责可编辑画板，测试负责独立检查。

## 阶段与责任

当前只做产品规格、Figma原型和各模块设计/验证计划。新版设计确认前，前端、后端、数据库和测试session均编写各自文档与接口提案，保护原有业务开发门槛。主Agent进行依赖协调、实际产物复核和评审整合；PR合并与正式发布由用户审批。
