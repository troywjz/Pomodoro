本轮目标：按已采纳的[责任分组](../../team/README.md)配置短任务 session。产品与交互设计承担当前 M0 需求与原型收尾，工程契约由独立任务统一维护；两者使用独立分支和工作树。Lead 负责范围协调、依赖、审批组织、交付复核与整合。

## 会话与工作树规则

1. 一个执行 session 对应一个明确交付物，使用新的独立工作树和任务分支。当前工具确认可用的执行模型为 `gpt-6-luna`；每次新派发重新核对可用模型。
2. 首轮不读取全部历史研究或旧聊天。后续按任务入口定位直接依赖，遇到字段冲突才检索具体来源。
3. session、机器路径、工作树附件和恢复信息写入本地忽略目录，公开文件只保存任务、版本、责任和依赖。
4. 交付包含 commit、路径清单、实际验证与证据、未决问题、下游变化；提交后停止本任务。Lead 检查真实 diff 和验证，再安排独立审查。
5. 审查与集成完成后按授权归档执行 session/工作树，下一独立任务创建新 session。历史对话继续保留可恢复记录。
